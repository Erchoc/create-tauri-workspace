一条命令，一个桌面应用

做出能自动更新的 macOS 和 Windows 应用。

一个 Tauri 2 工作区：React 负责界面，底下是职责清晰的两个 Rust crate，签名自动更新和跨平台发布流水线都已经接好。 

$ npx create-tauri-workspace my-app --identifier dev.you.myapp --repo you/my-app
开始使用 查看源码

生成器零运行时依赖。你交付的应用里也不含任何 JavaScript 运行时。

包含什么

那些自己接起来最麻烦的部分

签名自动更新

一条命令生成签名密钥、把公钥写进配置、并打印出要上传的 secret。 更新清单托管在 GitHub Releases 上，不需要你运维任何服务器。

设计体系，不只是换个皮

每一个颜色、圆角、间距都是 token。亮暗两套都定义好了，窗口里自带 主题切换。

两个 Rust crate，边界清晰

crates/core 承载可测试的逻辑，永不依赖 Tauri； crates/app 负责把它接到桌面外壳上。要加新 crate， 得先有真正的理由。

会提前失败的发布流水线

预检任务会在任何平台开始构建前先校验 tag、版本号和签名密钥。 产物落成草稿 Release，由你确认后再发布。

桌面软件的基本盘

单实例启动、窗口位置记忆、结构化日志、设置持久化，以及错误边界 ——渲染出错也不会只剩一个白窗口。

面向 AI 协作

一份 AGENTS.md，由 CLAUDE.md 引入， 外加一个 Claude Code 和 Codex 都能读的技能。

快速开始

从零到一个跑起来的窗口

  1. 检查本机环境

    $ npx create-tauri-workspace doctor

    它会逐项检查下面这些工具和平台 webview，并给出修复每一项的 确切命令。

    工具 最低版本 用途
    Bun 1.4 运行项目的全部命令
    Node.js 24 运行发布与更新配置脚本
    Rust 1.98 编译桌面应用本体

    这些版本约束的是你，不是你的用户：你交付出去的是原生二进制， 里面没有 JavaScript 运行时。

  2. 生成项目

    $ npx create-tauri-workspace my-app \
    --identifier dev.you.myapp \
    --repo you/my-app

    identifier 要用你自己控制的反向域名。没有域名就用 io.github.你的用户名.my-app。

  3. 跑起来

    $ cd my-app
$ bun run dev

  4. 打开自动更新

    $ bun run updater:init --repo you/my-app

    备份好它打印出来的私钥。这是唯一能给已安装的副本推送更新的 东西，丢了就再也补不回来。

  5. 发布

    $ bun run release:check
$ git tag v0.1.0 && git push origin v0.1.0

    macOS、Windows、Linux 并行构建，产物上传到草稿 Release。

给 AI 编程工具用

一份技能，Claude Code 和 Codex 都认

两个工具读的是同一种 SKILL.md 格式，只是目录不同。 安装命令会同时写入两处。 

$ npx create-tauri-workspace skill install          # 仅当前项目
$ npx create-tauri-workspace skill install --global # 所有项目
工具 安装位置
Claude Code .claude/skills/desktop-app/
Codex .agents/skills/desktop-app/

Claude Code 也可以按插件安装： /plugin marketplace add erchoc/create-tauri-workspace 然后 /plugin install desktop-app@create-tauri-workspace。

装好之后，说一句"帮我做个桌面应用"就够了。技能知道要挑 identifier、 要验证构建、要把业务逻辑挡在命令处理器外面、要用设计 token， 也知道在某件事需要付费账号时提前告诉你。

在你承诺上线时间之前，先读这段

三种签名，只有一种免费

它们很容易被搞混，而搞混它们是第一次发桌面应用翻车最常见的原因。

签名 签什么 不做会怎样 成本
更新签名 更新包 所有平台都无法自动更新 免费
Apple Developer ID .app 与 .dmg macOS 根本打不开 Apple 开发者计划
Windows 代码签名 .exe 安装包 SmartScreen 拦截告警 证书颁发机构

什么都不签会怎样

macOS 会告诉每一个下载你应用的人"文件已损坏"，并拒绝打开。 Windows 弹出警告，用户可以点掉。Linux 不受影响。

自动更新也需要 macOS 签名

更新会替换整个应用包。在 macOS 上，没签名的替换体启动不起来， 所以只有更新签名是不够的。

缺 secret 不会让构建失败

发布流水线会跳过每一个 secret 为空的签名步骤，所以没配置凭据的 仓库仍然能产出未签名的构建，而不是直接报错。

完整的分发指南 列出了每一个 secret 以及去哪里获取。

常见问题

老实的回答

构建 macOS 应用一定要有 Mac 吗？
本地构建需要。但内置的发布流水线用的是 GitHub 的 macOS runner， 所以你不用拥有 Mac 也能发布 macOS 构建——只是签名和公证仍然需要 Apple 开发者账号。
和官方的 Tauri 脚手架有什么区别？
create-tauri-app 让你自由选择技术栈的每一部分， 到此为止。这个项目替你把选择做完了，并补上了你本来要手写的部分： crate 边界、签名更新、设计 token 体系、发布预检，以及给 AI 工具的规范。
应用里会带 Node.js 或 Bun 吗？
不会。Bun 只是开发工具。生产构建会把编译好的静态前端嵌进一个 Rust 二进制里。
可以不用自动更新吗？
可以。在你运行 bun run updater:init 之前，更新是 关着的。没有签名密钥时更新插件根本不会注册，界面会隐藏更新入口， 而不是提供一个自己无法校验的安装包。
更新签名的私钥丢了会怎样？
所有已安装的副本都将无法再接收更新，这些用户只能手动重新下载 安装包。所以在配置命令打印出私钥位置时，立刻备份它。
支持 Linux 吗？
支持——CI 会构建 AppImage 和 Debian 包。macOS 和 Windows 是主要 目标，Linux 是顺带的。
